### Overall Architecture

So let's start off by talking about the hypervisor that I'll use to run all my containers and VMs in!

<ins>Proxmox, Hypervisors, VMs, and LXCs</ins>
A VM - short for virtual machine - is a virtual emulation of a computer within a computer. It runs its own independent operating system and apps, is given a subset of its host machine's compute resources (CPU, RAM, storage), and is completely isolated from the rest of the system.

Proxmox VE is a hypervisor built on top of Linux, meaning that it acts as a host for some several VMs that might run on a single machine. There are 2 types of hypervisors that exist: Type 1 hypervisors don't require a host OS to function and are able to run directly on the resources provided by the machine, and type 2 hypervisors run as an app on top of an OS and rely on it to manage compute resources. Each have their separate use case but in mine, I chose Proxmox, which is a type 1 so that I can maximize my compute resources and efficiency.

LXCs - short for Linux Containers - are similar to VMs in the sense that they both provide isolated environments to run software on. The main differences are that LXCs are exclusive to Linux and share the host machine's kernel. As a result, the hypervisor and LXC aren't completely isolated. LXCs can be better in situations where compute resources are a significant constraint and a kernel that doesn't differ from the host machine's kernel can be used, which leads to slightly less flexibility, independence, and security (host kernel compromization means all containers are compromised). All the services I plan on hosting on this machine (cloud storage, logging, backups, dashboard etc) don't necessarily require their own kernel so I plan on utilizing a mix of VMs and LXCs to save on compute.
